# Проверка обязательной версии

Этот документ описывает воспроизводимую проверку обязательной версии.

## Результаты проверки 23 сентября 2026

- `npm test`: 142 теста в пяти файлах прошли (56 валидатор, 24 симулятор, 47 API, 13 UI, 2 проверенные факты).
- `npm run typecheck` и `npm run build`: успешно; собраны фронтенд и Node.js-сервер.
- Проверены оба режима запуска: `npm run dev` и production через `npm start`.
- В production-интерфейсе выполнен настоящий запрос к OpenAI, модель `gpt-4o-mini`: показан источник «Анализ LLM», контрольный результат 56,54, бюджет 95/100, критических показателей 0.
- LLM выбирает и ранжирует проверенные факты; сервер формирует объяснение и повторно рассчитывает предлагаемые замены. Устранённые дефициты Нуры не отображаются как текущие.
- Браузерный проход: пустой набор → пять решений → результат → объяснение → удаление решения. После изменения показана отметка об устаревшем анализе, новый запрос недоступен до завершения набора.
- Проверен экран 375×812: горизонтальной прокрутки нет, длинные рекомендации помещаются. Ошибок в консоли браузера нет.
- Проверено отсутствие значения серверного ключа в собранных браузерных файлах. Секретные файлы исключены из Git.

Альтернативные совместимые провайдеры не участвовали в живой проверке.

## Проверка в браузере

1. Открыть http://127.0.0.1:3001 после production-сборки.
2. В новом профиле браузера проверить пустой набор (0/5), бюджет 100 и отсутствие итогового Score. При повторном посещении должен восстановиться черновик; для пустого набора используйте сброс.
3. Загрузить пример ТЗ: 95/100, пять решений, Score 56,54, прирост 3,99, N_crit 0.
4. Запросить анализ. При настроенном рабочем ключе API должен вернуть source=llm; без ключа — явно обозначенный source=rules.
5. Удалить решение: итог не рассчитан, старый анализ помечен устаревшим.
6. Повторно выбрать меру, изменить район, проверить новый расчёт и новый анализ.
7. Проверить блокировку шестой меры, перерасхода, третьей меры направления и конфликтов.
8. Повторить основной проход при ширине 375px, проверить отсутствие горизонтальной прокрутки.
9. Проверить отсутствие кнопок экспериментальных опций при выключенном флаге; кнопка «Сценарии» должна быть доступна.

## Проверка сохранения и сравнения

1. Выбрать две допустимые меры и другой район на карте, обновить страницу: набор 2/5 и район должны восстановиться без запроса AI.
2. Загрузить эталон, открыть «Сценарии», сохранить его с названием. Проверить Score 56,54, бюджет 95/100 и ноль критических показателей.
3. Сбросить решения, обновить страницу: черновик пустой, сохранённый эталон остаётся в библиотеке.
4. Загрузить сохранённый эталон, изменить решения и сохранить второй вариант. Первая запись должна оставаться неизменной.
5. Выбрать варианты A и B. Проверить разницы B − A, оценки пяти районов, десять показателей выбранного района и списки мер. Переставить A/B через пустой выбор: знаки разниц меняются.
6. Удалить одну из выбранных записей: соответствующий выбор сравнения очищается, текущий черновик остаётся прежним.
7. Запросить AI-анализ, затем загрузить сценарий из библиотеки до завершения запроса. Поздний ответ не должен появиться как актуальный. Сохранение и выбор пары сами по себе не делают анализ устаревшим.
8. Проверить Escape, циклический переход Tab внутри окна и возврат фокуса на «Сценарии» после закрытия.
9. Повторить сохранение и сравнение при ширине 375px и 1280px: нет прокрутки всей страницы по горизонтали, содержимое таблиц доступно внутри окна.

Повреждённые данные, ошибки чтения/записи и запрет сохранения при кризисах проверяются автоматическими тестами. Ключи хранилища версионированы; миграция прежнего прототипа не требуется, поскольку он не сохранял записи между сеансами.
