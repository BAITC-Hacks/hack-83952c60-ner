# «Аким на 5 часов»

Учебный симулятор распределения бюджета Астаны: 100 условных единиц, ровно пять решений, пять условных районов и десять показателей. Результаты рассчитывает детерминированный движок, а языковая модель объясняет последствия. Данные синтетические; приложение не прогнозирует реальное развитие города.

## Запуск

Требуется Node.js 22.12+ и npm. Команды выполняются из корня проекта.

```powershell
npm ci
Copy-Item .env.example .env
# Заполните OPENAI_API_KEY в .env локально.
npm run dev
```

Если файл `.env` уже существует, не перезаписывайте его. Интерфейс: http://127.0.0.1:3000, API: http://127.0.0.1:3001. Команда запускает оба процесса; Ctrl+C завершает их. Vite передаёт запросы /api серверу; его адрес берётся из тех же HOST и PORT.

```powershell
npm test
npm run typecheck
npm run build
npm start
```

После сборки `npm start` обслуживает интерфейс и API по адресу http://127.0.0.1:3001. `npm run preview` предназначен только для просмотра фронтенд-сборки, без API; для полной проверки используйте `npm start`.

### Запуск через Docker

Сборка и запуск в изолированном контейнере:

```powershell
# Запуск через Docker Compose (порт 3001)
docker compose up --build

# Или прямая сборка и запуск контейнера:
docker build -t akim-astana-simulator .
docker run -p 3001:3001 --env-file .env akim-astana-simulator
```

Интерфейс и API будут доступны по адресу: **http://localhost:3001** (или http://127.0.0.1:3001).

## Настройка LLM

| Переменная | По умолчанию | Назначение |
|---|---|---|
| OPENAI_API_KEY | пусто | Серверный ключ OpenAI |
| OPENAI_MODEL | gpt-4o-mini | Модель с Responses API и Structured Outputs |
| HOST | 127.0.0.1 | Интерфейс сервера |
| PORT | 3001 | Порт сервера |
| VITE_ENABLE_EXPERIMENTS | false | Показывать экспериментальные прототипы |

Ключ не вводится в браузере, не включается в Vite-переменные, ответы API или логи. Файлы `.env`, `.env.*` и `*.env` исключены из Git, кроме безопасного `.env.example`. Для загрузки нового ключа перезапустите сервер.

LLM вызывается только кнопкой «Получить AI-анализ» или отправкой вопроса. Сервер использует официальный OpenAI SDK, Responses API, структурированный ответ, отключённые повторы и лимит ожидания 20 секунд. Ответы не сохраняются провайдером через параметр `store: false`.

При отсутствии ключа, ошибке, таймауте или некорректном ответе модель заменяется явно обозначенным **анализом по правилам**. Математика продолжает работать, но резервный режим не является настоящим AI-анализом. Проверка живого подключения должна получить `source: "llm"`.

## Основной сценарий

1. Откройте приложение: бюджет 100, выбрано 0/5, итоговый Score ещё не рассчитан.
2. Выберите пять мер. Для районной меры укажите район; городская действует на все пять.
3. Изучите Score, его составляющие, карту и показатели до/после.
4. Запустите AI-анализ или задайте вопрос. Источник ответа указан в интерфейсе.
5. Измените решение: предыдущий анализ будет помечен устаревшим. Поздний ответ на старый сценарий не заменяет актуальный.
6. Для воспроизводимого примера нажмите «Эталон ТЗ» (контрольный набор).

Бюджетный остаток не приносит бонуса и не штрафуется. Требуется ровно пять мер, максимум две одного направления; по одной в каждом направлении не требуется.

## Правила и расчёт

Общий валидатор используется браузером и сервером. Он запрещает перерасход, повторы, неизвестные ID, некорректную структуру входа, шестую меру, третью меру одного направления и несовместимости:

- M1 и M3 — в любых районах.
- M4 и M7 — в одном районе.
- M5 и M13 — в одном районе.

У районной меры район обязателен, у городской поле района отсутствует. Невалидный сценарий возвращает причины и `finalScore: null`, а не нулевой балл. При неполном выборе отображаются исходные показатели; итог сценария появляется после пяти допустимых решений.

Для каждого показателя:

```text
I'[d,k] = clip(I[d,k] + Σ(effect[m,k] × (8 − lag[m])/8) + synergies[d,k], 0, 100)
D[d] = Σ(weight[k] × I'[d,k])
D_avg = Σ(populationShare[d] × D[d])
Score = 0.7 × D_avg + 0.3 × min(D[d]) − N_crit
```

Горизонт — восемь кварталов. Все показатели направлены одинаково: больше — лучше. N_crit — число пар «район × показатель» со значением строго ниже 40. Синергии фиксированы и не масштабируются лагом: M1+M2 даёт T1+2 в районе M1, M10+M12 даёт B1+2 в районе M10, M5+M6 даёт E2+2 в районе M5. Округление применяется только при отображении.

| Контроль | Точное значение | Отображение |
|---|---:|---:|
| Базовый D_avg | 56.8624 | 56.86 |
| Базовый Score | 52.55768 | 52.56 |
| Score контрольного набора | 56.54307 | 56.54 |
| Прирост контрольного набора | 3.98539 | +3.99 |

Контрольный набор: M7, M8 и M10 в Нуре; M12 — город; M5 — Сарыарка. Стоимость 95, остаток 5, N_crit=0, синергия M10+M12. Указанное в ТЗ ≈56.5 — приблизительное число, не требование получить ровно 56.50.

## Архитектура и API

- `src/data/`: исходные районы, показатели, меры, синергии и несовместимости.
- `src/engine/`: общий валидатор и математический движок, независимые от UI и LLM.
- `src/components/`: выбор решений, карта, графики, Score и панель анализа.
- `src/ai/`: HTTP-клиент, управление актуальностью запросов и резервный анализ по правилам.
- `server/`: Express API, контекст расчёта, серверный клиент OpenAI, проверка ответа и обработка ошибок.
- `tests/`: расчёты, валидация, API и поведение интерфейса.
- `dist/`, `dist-server/`: результаты сборки, не исходники.

`GET /api/health` возвращает состояние сервера и булев признак настройки LLM, без ключа.

`POST /api/analyze` принимает только решения и необязательный непустой вопрос до 2000 символов:

```json
{
  "decisions": [
    {"measureId": "M7", "districtId": "nura"},
    {"measureId": "M8", "districtId": "nura"},
    {"measureId": "M10", "districtId": "nura"},
    {"measureId": "M12"},
    {"measureId": "M5", "districtId": "saryarka"}
  ],
  "question": "Какие компромиссы есть у этого сценария?"
}
```

Успешный ответ: `{simulation, analysis, answer?, source, reason?}`. `simulation` вычисляется сервером, `analysis` содержит резюме, сильные стороны, риски, выводы по районам и рекомендации. `source` — `llm` или `rules`; причина резервного режима — `missing_key`, `timeout`, `provider_error` или `invalid_response`.

Для защиты от выдуманных последствий LLM выбирает и ранжирует идентификаторы проверенных фактов, включая факты для ответа на вопрос. Сервер собирает текст из этих фактов: модель не может заменить числа, приписать району отсутствующий критический показатель или добавить неизвестную меру. Районные предупреждения формируются непосредственно из расчёта. Варианты одной замены предварительно проходят валидатор и повторную симуляцию; это локальные улучшения, а не доказательство глобального оптимума. При `source: llm` приоритеты выбирает языковая модель, при `source: rules` используется фиксированная сводка.

Ошибки: 400 — формат запроса, 422 — нарушение правил сценария (модель не вызывается), 413 — тело больше 16 КБ. Клиент не может передать собственный Score. Сервер передаёт модели рассчитанные показатели, эффекты мер с лагами, синергии и части формулы. Числовые карточки UI всегда используют движок. Каждый предложенный вариант замены рассчитан отдельно; совместное применение нескольких замен требует нового расчёта.

## Проверки и ограничения

`npm test` проверяет точные контрольные значения с допуском 1e-6, восемь правил, прототипные ID, бюджетные границы, порядок решений, лаги, синергии, отрицательный эффект M11, clip и порог 40. API-тесты используют подставной провайдер и проверяют ответ LLM, формат, недопустимые сценарии, ошибки, отсутствие ключа, таймаут и поздние ответы. UI-тесты проверяют доступность анализа и смену сценария во время запроса.

Карта является условной схемой пяти районов датасета. Обязательная версия предназначена для локальной демонстрации, без регистрации, БД и публикации в интернете.

Кризисы, сравнение команд, оптимизатор и презентация сохранены как экспериментальные прототипы и по умолчанию скрыты. У них остаются известные ограничения: несогласованный учёт событий, сохранённые вручную оценки, ранжирование и печать. Они не входят в приёмку основной версии. Включение флага требует перезапуска Vite или новой сборки.
