## 1. Проблема и Ценность решения

При принятии решений по развитию Астаны необходимо одновременно балансировать 5 ключевых направлений:
- **Транспорт** (пробки на мостах, интервалы автобусов, LRT).
- **Экология и озеленение** (зимний смог частного сектора, ветрозащитный зеленый пояс).
- **Социальная инфраструктура** (дефицит мест в школах, трехсменка, поликлиники).
- **Безопасность** (Safe City, видеонаблюдение «Сергек», концепция Vision Zero).
- **Городские сервисы и ЖКХ** (надежность теплосетей в 35-градусные морозы, цифровой сервис iKomek 109).

Ограниченность бюджета требует точной оценки сценариев: куда вложить ресурсы, чтобы подтянуть отстающие районы (Нура, Сарыарка) и не допустить критических аварий в Алматы и Есиле.

**AI-симулятор «Аким на 5 часов»** дает городскому управленцу объективный инструмент принятия решений, исключающий субъективизм и мгновенно показывающий системные последствия каждого шага.

## 2. Ключевые возможности

### ✅ Must-Have требования (100% реализация):
1. **Единый виртуальный бюджет**: строго 100 у.е. для всех пользователей.
2. **5 обязательных решений**: ровно 5 решений по направлениям Транспорт, Экология, Соцсфера, Безопасность, Сервисы.
3. **Автоматический контроль бюджета**: мгновенная валидация перерасхода, запрет повторов мер, контроль не более 2 мер на одно направление.
4. **Детерминированный математический движок**: точный расчет эффектов мер с учетом временного лага, фиксированных синергий, несовместимостей и штрафов за критические дефициты ($N_{crit} < 40$).
5. **Astana Quality of Life Score**: итоговая комплексная оценка качества жизни в столице.
6. **Agentic AI Анализ**: глубокий синтез сильных сторон, скрытых рисков, компромиссов и территориальных последствий.

### 🌟 Опциональные возможности (Все 5 из 5 реализованы):
1. **Сравнение команд и сценариев (Leaderboard)**: сохранение прогонов команд, A/B сравнение дельт и затрат.
2. **Интерактивная карта 5 районов Астаны**: векторная тепловая карта (Есиль, Алматы, Сарыарка, Байконур, Нура), разделительная линия реки Есиль, отображение размещенных мер и детальный инспектор показателей района.
3. **AI-Оптимизатор сценариев (Smart Recommender)**: алгоритмический поиск наиболее выгодных замен с подсчетом точного прироста баллов (+X.XX) и применением в один клик.
4. **Моделирование непредвиденных городских кризисов (Форс-мажоры)**: стресс-тестирование стратегии на устойчивость при аномальном буране, прорыве теплотрасс, смоге или миграционном скачке.
5. **Автоматическая генерация презентации**: готовый исполнительный слайд для защиты перед комиссией с экспортом в PDF и копированием в буфер обмена.

## 3. Математическая модель и формулы

Расчет производится строго по утвержденной формуле ТЗ:

### Шаг 1. Пересчет показателей района $d$ и показателя $k$:
$$I'_{dk} = \text{clip}\left(I_{dk} + \sum_{m} \text{effect}_{m,k} \times \frac{8 - L_m}{8} + \text{synergies}_{d,k}, 0, 100\right)$$
- Горизонт симуляции: $H = 8$ кварталов (2 условных года).
- $L_m$: лаг внедрения мероприятия (1..4 квартала).
- Для мер типа «Район» эффект получает только выбранный район; для мер типа «Город» — все 5 районов.
- Бонусы синергий фиксированы и лагом не масштабируются.

### Шаг 2. Оценка района $D_d$:
$$D_d = \sum_{k=1}^{10} w_k \cdot I'_{dk}$$

Веса 10 показателей ($\sum w_k = 1.00$):
| Код | Направление | Показатель | Вес $w_k$ |
|---|---|---|---|
| **T1** | Транспорт | Разгрузка дорог (100 = нет пробок) | **0.10** |
| **T2** | Транспорт | Доступность общественного транспорта | **0.10** |
| **E1** | Экология | Озеленение (≥20 м² на жителя) | **0.09** |
| **E2** | Экология | Качество воздуха (AQI ≤50 зимой) | **0.11** |
| **S1** | Соцсфера | Школы и детсады (без 2-й и 3-й смен) | **0.11** |
| **S2** | Соцсфера | Поликлиники и первичная медпомощь | **0.11** |
| **B1** | Безопасность | Безопасность улиц (освещение и камеры) | **0.09** |
| **B2** | Безопасность | Безопасность дорожного движения (Vision Zero) | **0.09** |
| **C1** | Сервисы | Надёжность ЖКХ (отсутствие аварий сетей) | **0.10** |
| **C2** | Сервисы | Скорость закрытия обращений (iKomek 109) | **0.10** |

### Шаг 3. Средневзвешенный общегородской балл $D_{avg}$:
$$D_{avg} = \sum_{d} \text{pop}_d \cdot D_d$$
Доли населения ($\text{pop}_d$):
- **Есиль**: 0.27
- **Алматы**: 0.24
- **Сарыарка**: 0.20
- **Нура**: 0.16
- **Байконур**: 0.13

### Шаг 4. Итоговый Score:
$$\text{Score} = 0.7 \cdot D_{avg} + 0.3 \cdot \min(D_d) - 1.0 \cdot N_{crit}$$
- **Базовый Score без решений**: **52.56** ($0.7 \times 56.86 + 0.3 \times 49.18 - 2$).
- $N_{crit}$: количество пар «район $\times$ показатель» со значением строго $< 40$. В базе: Нура $S1=38$ и $S2=35$ ($N_{crit}=2$).
- Контрольный набор ТЗ (`M7`+`M8`+`M10` в Нуре, `M12` город, `M5` в Сарыарке): стоимость 95 у.е., **Score = 56.54** ($+3.99$, $N_{crit}=0$).

| **M12** | Единая платформа обращений | Сервисы | Город | 14 | 1 | C2 +5 |
| **M13** | Модернизация тепло- и водосетей | Сервисы | Район | 28 | 4 | C1 +18, E2 +2 |
| **M14** | Аварийные бригады ЖКХ | Сервисы | Город | 16 | 1 | C1 +5, C2 +2 |

### Синергии (бонус без урезания лагом):
1. **M1 + M2**: `T1 +2` в районе M1 (синхронизация полос и ИТС).
2. **M10 + M12**: `B1 +2` в районе M10 (камеры Safe City + платформа iKomek).
3. **M5 + M6**: `E2 +2` в районе M5 (газификация + ветрозащитный пояс).

### Запрещенные несовместимости:
- **M1 и M3**: либо BRT, либо LRT (в любых районах).
- **M4 и M7**: нельзя в одном районе (конфликт за земельный участок).
- **M5 и M13**: нельзя в одном районе (дублирование программ ЖКХ).

## 5. Архитектура проекта и Agentic AI

Проект спроектирован по модульному принципу чистой архитектуры:

```
src/
├── data/
│   ├── districts.ts         # Базовые показатели 5 районов Астаны
│   ├── indicators.ts        # 10 индикаторов, веса и направления
│   ├── measures.ts          # 14 мероприятий, синергии, конфликты
│   └── events.ts            # Городские форс-мажоры для стресс-тестов
├── engine/
│   ├── types.ts             # Строгая TypeScript типизация
│   ├── validator.ts         # Валидатор 8 регламентных правил
│   ├── simulator.ts         # Математическое ядро расчета Score
│   └── optimizer.ts         # Алгоритм поиска лучших комбинаций
├── ai/
│   ├── analyzer.ts          # Agentic AI: глубокий анализ компромиссов
│   ├── llmClient.ts         # Клиент: офлайн-интеллект + опциональный Live LLM
│   └── advisor.ts           # Стратегические подсказки
├── components/
│   ├── Header.tsx           # Таймер 5 часов, кнопки пресетов и действий
│   ├── ScoreDashboard.tsx   # Индикатор Score с декомпозицией формулы
│   ├── BudgetBar.tsx        # Контроль 100 у.е. и 5 слотов решений
│   ├── DistrictMap.tsx      # Векторная интерактивная карта районов
│   ├── DecisionPanel.tsx    # Выбор мер с фильтром синергий/конфликтов
│   ├── RadarAnalytics.tsx   # Аналитика 10 показателей до и после
│   ├── AIInsightCard.tsx    # Аналитический отчет и чат с советником
│   ├── OptimizerCard.tsx    # Рекомендации оптимизатора в 1 клик
│   ├── CompareModal.tsx     # Лидерборд и сравнение команд
│   ├── CrisisModal.tsx      # Симулятор форс-мажоров
│   └── PresentationModal.tsx # Генерация презентационного слайда Акима
├── App.tsx                  # Главный координирующий компонент
├── main.tsx                 # Входная точка React
└── index.css                # Дизайн-система (Dark Mode, Glassmorphism)
```

### Принцип работы Agentic AI:
> **Согласно разделу 3 ТЗ**: ИИ не «придумывает» и не рассчитывает числа самостоятельно. Математический движок передает структурированные дельты, веса и штрафы агенту, который:
> 1. Формирует вердикт управленческого стиля (например, *«Стратег инклюзивного развития»*).
> 2. Диагностирует ликвидацию пространственных диспропорций (фокус на Нуру).
> 3. Выявляет неиспользованные синергии и долгосрочные инвестиционные риски.
> 4. Отвечает на интерактивные вопросы пользователя в режиме советника.

## 6. Быстрый запуск и воспроизводимость

Проект не требует настройки внешних серверов баз данных и запускается за 30 секунд.

### Системные требования:
- **Node.js**: v18+ (протестировано на Node.js v24.12.0)
- **npm**: v9+ (протестировано на npm 11.7.0)

### Шаги установки и запуска:

```bash
# 1. Клонирование репозитория
git clone <url_репозитория>
cd hack-83952c60-ner

# 2. Установка зависимостей
npm install

# 3. Запуск dev-сервера симулятора
npm run dev
```

Приложение откроется по адресу: **`http://localhost:3000/`**

### Сборка production-бандла:
```bash
npm run build
npm run preview
```
