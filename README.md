# «Аким на 5 часов»

**Учебный симулятор распределения городского бюджета Астаны с объяснением результатов через AI.**

[Открыть deployed-версию](https://fiveh-akim.onrender.com/) · [Проверить состояние API](https://fiveh-akim.onrender.com/api/health)

## О проекте

Как распределить ограниченный бюджет между транспортом, экологией, социальной инфраструктурой, безопасностью и ЖКХ, учитывая потребности разных районов? Проект позволяет исследовать этот вопрос на учебной модели: пользователь принимает роль акима, выбирает пять решений и видит, как они меняют показатели качества жизни.

Симулятор подходит для участников и жюри хакатона, а также для учебного разбора управленческих компромиссов. Он показывает не только общий результат, но и положение слабейшего района, критические дефициты и отложенные эффекты вложений.

> Данные синтетические. Это демонстрационная модель, а не прогноз развития Астаны и не инструмент принятия реальных бюджетных решений. Числа рассчитывает детерминированный движок; языковая модель выбирает значимые факты для объяснения.

## Что реализовано

- Каталог **14 мер** по пяти направлениям с ценой, эффектами и задержкой реализации.
- Выбор районных и общегородских мер: **100 условных единиц бюджета**, **ровно пять решений**, не более двух мер одного направления.
- Проверка бюджета, повторов, назначения района и несовместимых решений с объяснением ошибок.
- Модель пяти районов: **Есиль, Алматы, Сарыарка, Байконур и Нура**; десять показателей качества жизни.
- Расчёт Astana Quality of Life Score, прироста относительно исходного состояния, среднего результата города, оценки слабейшего района и критических показателей.
- Интерактивная схематическая карта районов и показатели до/после выбранных мер.
- Учёт задержек на горизонте восьми кварталов, отрицательных эффектов и трёх синергий между мерами.
- Серверный AI-анализ: резюме, сильные стороны, риски, последствия для районов, рекомендации и необязательный вопрос советнику.
- Явно обозначенный анализ по правилам при отсутствии ключа или сбое модели; числовой расчёт остаётся доступен.
- Пометка устаревшего анализа при изменении сценария и защита от подмены актуального ответа поздним ответом на старый запрос.
- Кнопка **«Эталон ТЗ»** для воспроизводимой демонстрации и сброс выбранных решений.

## Как работает решение

1. Пользователь открывает приложение без регистрации. В начале доступно 100 у.е., выбрано 0 из 5 решений.
2. Выбирает меры из каталога. Для районной меры указывает район; общегородская применяется ко всем пяти районам.
3. Валидатор проверяет ограничения при добавлении. До полного допустимого набора интерфейс показывает исходные показатели, итоговый Score ещё не рассчитан.
4. После пяти допустимых решений движок рассчитывает последствия: обновляет показатели, районные оценки и общий Score.
5. Пользователь изучает карту и изменения показателей, затем нажимает **«Получить AI-анализ»**, при необходимости указав вопрос.
6. Сервер повторно проверяет и рассчитывает сценарий, формирует доказанные факты и передаёт их модели. Модель выбирает и ранжирует идентификаторы фактов; сервер проверяет ответ и собирает текст из подготовленных утверждений.
7. Пользователь меняет решения, сравнивает новый результат с исходным и обновляет анализ.

### Правила и формула

Каждую меру можно выбрать только один раз, даже для разных районов. Необязательно брать по одной мере из каждого направления. Остаток бюджета не даёт бонуса и не штрафуется.

Несовместимости:

| Пара мер | Ограничение |
|---|---|
| M1 — автобусные полосы и M3 — ЛРТ | Нельзя сочетать независимо от района |
| M4 — парк и M7 — школа/детсад | Нельзя сочетать в одном районе |
| M5 — чистое топливо и M13 — модернизация сетей | Нельзя сочетать в одном районе |

Расчёт основной версии без экспериментальных событий:

```text
I'[d,k] = clip(I[d,k] + Σ(effect[m,k] × (8 − lag[m]) / 8) + synergy[d,k], 0, 100)
D[d]    = Σ(weight[k] × I'[d,k])
D_avg   = Σ(populationShare[d] × D[d])
Score   = 0.7 × D_avg + 0.3 × min(D[d]) − N_crit
```

Здесь `d` — район, `k` — показатель, `m` — применимая к району выбранная мера; `lag` — задержка в кварталах. `clip` ограничивает показатель диапазоном 0–100. Чем больше показатель, тем лучше. `N_crit` — количество пар «район × показатель» со значением **строго ниже 40**. Промежуточные значения не округляются.

Синергии добавляются без уменьшения на лаг: M1+M2 даёт +2 к T1 в районе M1; M10+M12 — +2 к B1 в районе M10; M5+M6 — +2 к E2 в районе M5.

## Архитектура

```text
Браузер: React
  ├─ каталог и исходные данные (src/data)
  ├─ общий валидатор и симулятор (src/engine) → карта, показатели, Score
  └─ POST /api/analyze: решения + необязательный вопрос
       ↓
Express API
  ├─ повторная валидация и расчёт тем же движком
  ├─ подготовка контекста, фактов и проверенных вариантов одной замены
  ├─ вызов LLM → проверка выбранных идентификаторов → сборка объяснения
  └─ резервный анализ по правилам при недоступности LLM
       ↓
Ответ: simulation + analysis + source + необязательный answer
```

| Путь | Назначение |
|---|---|
| `src/App.tsx`, `src/components/` | Состояние сценария и пользовательский интерфейс |
| `src/data/` | Районы, показатели, меры, синергии, несовместимости и экспериментальные события |
| `src/engine/validator.ts` | Общие ограничения входных данных и решений |
| `src/engine/simulator.ts` | Расчёт показателей и Score |
| `src/engine/optimizer.ts` | Поиск вариантов замены мер для улучшения сценария |
| `src/ai/` | HTTP-клиент, актуальность запросов и анализ по правилам |
| `server/app.ts`, `server/index.ts` | HTTP-маршруты, запуск сервера и раздача production-сборки |
| `server/context.ts`, `server/facts.ts`, `server/analysis.ts` | Контекст, проверенные факты, вызов и проверка ответа модели |
| `tests/` | Тесты расчётов, валидации, фактов, API и UI |
| `Dockerfile`, `docker-compose.yml`, `render.yaml` | Контейнеризация и конфигурация размещения |

В разработке Vite проксирует `/api` на Express. В production один Express-сервер обслуживает API и статические файлы из `dist/`; серверная сборка находится в `dist-server/`. База данных не используется, выбранный сценарий хранится в состоянии React.

## Установка и запуск

### Локальная разработка

Требуются **Node.js 22.12 или новее** и **npm**. Скачайте репозиторий и откройте терминал в его корневой папке.

1. Установите зависимости:

   ```sh
   npm ci
   ```

2. Создайте файл окружения, если его ещё нет. Для PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

   Для Linux/macOS:

   ```sh
   cp .env.example .env
   ```

   Существующий `.env` не перезаписывайте. Для первого запуска ключ не нужен: симулятор и анализ по правилам работают без него.

3. Запустите интерфейс и API одной командой:

   ```sh
   npm run dev
   ```

4. Откройте [интерфейс](http://127.0.0.1:3000). API доступен на [порту 3001](http://127.0.0.1:3001/api/health). Для остановки нажмите `Ctrl+C`.

### Настройка AI и окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | Пусто | Серверный ключ для вызова модели |
| `OPENAI_MODEL` | `gpt-4o-mini` | Имя модели |
| `OPENAI_BASE_URL` | Не задано | Альтернативный совместимый endpoint; включает ветку Chat Completions |
| `HOST` | `127.0.0.1` | Адрес привязки API; в контейнере — `0.0.0.0` |
| `PORT` | `3001` | Порт API; также используется Vite для проксирования |
| `VITE_ENABLE_EXPERIMENTS` | `false` в примере окружения | Показ экспериментальных функций; учитывается при запуске Vite или сборке |

Для OpenAI заполните `OPENAI_API_KEY` в `.env` и перезапустите сервер. Ключ остаётся на сервере: не помещайте его в переменные `VITE_*` и не коммитьте `.env`.

В сервере также предусмотрены `NVIDIA_API_KEY`, `NVIDIA_BASE_URL`, `NVIDIA_MODEL`, а для ключа и адреса — `BREV_API_KEY`, `BREV_BASE_URL`. В `.env.example` есть пример NVIDIA endpoint и модели `meta/llama-3.1-70b-instruct`. Это настройка совместимого провайдера, а не подтверждение его доступности или подключения на деплое.

При использовании этих альтернатив удалите неиспользуемые `OPENAI_API_KEY` и `OPENAI_BASE_URL`: даже пустые значения этих переменных имеют приоритет перед альтернативами. Для `NVIDIA_MODEL` также уберите заданный в примере `OPENAI_MODEL=gpt-4o-mini` или явно укажите нужную модель в `OPENAI_MODEL`.

Лимит ожидания модели — 20 секунд, автоматические повторы SDK отключены. В ветке Responses API передаётся `store: false`. При ошибке, таймауте или непрошедшем проверку ответе сервер возвращает анализ по правилам с причиной переключения. Реальное использование LLM подтверждается полем `source: "llm"`; `llmConfigured: true` в health-check означает только наличие настроенного провайдера.

После сборки интерфейс и API доступны на [http://127.0.0.1:3001](http://127.0.0.1:3001). Команда `npm run preview` запускает только просмотр фронтенд-сборки без API; для полного приложения используйте `npm start`.

При необходимости задайте `OPENAI_API_KEY`, `OPENAI_MODEL` и `OPENAI_BASE_URL` в окружении сервиса. Ключ не нужен для работы расчётного движка и резервного анализа.

## Как проверить решение

### Сценарий для жюри

1. Откройте [демо](https://fiveh-akim.onrender.com/) или локальный экземпляр.
2. Нажмите **«Эталон ТЗ»**. Загрузится следующий набор:

   | Мера | Где применяется | Стоимость, у.е. |
   |---|---|---:|
   | M7 — школа и детсад | Нура | 24 |
   | M8 — центр семейного здоровья | Нура | 20 |
   | M10 — освещение и камеры | Нура | 12 |
   | M12 — цифровая платформа обращений | Весь город | 14 |
   | M5 — перевод на чистое топливо | Сарыарка | 25 |

3. Сверьте результат с контрольными значениями движка и тестов:

   | Проверка | Ожидаемое значение |
   |---|---:|
   | Выбрано решений | 5 |
   | Потрачено / остаток | 95 / 5 у.е. |
   | Исходный Score | 52.56 |
   | Итоговый Score | **56.54** (до округления: 56.54307) |
   | Прирост Score | **+3.99** |
   | Критических показателей после мер | 0 |
   | Активная синергия | M10 + M12 |

4. Выберите Нуру на карте: S1 должен измениться с 38 до 48, S2 — с 35 до 43.75. Эти изменения выводят оба показателя из критической зоны.
5. Введите вопрос «Какие компромиссы есть у этого сценария?» и нажмите **«Получить AI-анализ»**. Проверьте метку источника: **«Анализ LLM»** либо **«Анализ по правилам»** с объяснением причины. Во втором случае индивидуальный ответ модели недоступен, но расчёт и сводка работают.
6. Удалите одну меру: итоговый Score перестанет отображаться как результат полного сценария, предыдущий анализ будет помечен устаревшим. Верните допустимое пятое решение и обновите анализ.
7. Для проверки ограничений сбросьте сценарий, добавьте M1 в одном районе и попробуйте выбрать M3: несовместимая комбинация не должна добавиться.

| Источник | Содержание |
|---|---|
| `src/data/districts.ts` | Пять районов, доли населения, профили и исходные показатели |
| `src/data/indicators.ts` | Десять показателей, описания и веса |
| `src/data/measures.ts` | Каталог из 14 мер, стоимость, лаги, эффекты, синергии и несовместимости |
| `src/data/events.ts` | События для экспериментального режима |
| OpenAI / совместимый API | Необязательный внешний анализ рассчитанного сценария и вопроса |
| Google Fonts | Загрузка шрифтов интерфейса |
| Render | Размещение опубликованного приложения; конфигурация включена в репозиторий |

Названия Safe City, «Сергек» и iKomek 109 встречаются в описаниях учебных мер. Реальных интеграций с этими городскими системами в коде нет.

### HTTP API приложения

- `GET /api/health` → `{ "status": "ok", "llmConfigured": false }` (флаг зависит от конфигурации).
- `POST /api/analyze` принимает решения и необязательный непустой вопрос до 2000 символов. Пример тела:

```json
{
  "decisions": [
    { "measureId": "M7", "districtId": "nura" },
    { "measureId": "M8", "districtId": "nura" },
    { "measureId": "M10", "districtId": "nura" },
    { "measureId": "M12" },
    { "measureId": "M5", "districtId": "saryarka" }
  ],
  "question": "Какие компромиссы есть у этого сценария?"
}
```

Ответ содержит `simulation`, `analysis`, `source`, необязательные `answer` и `reason`. Источник — `llm` или `rules`; причины резервного режима: `missing_key`, `timeout`, `provider_error`, `invalid_response`.

Сервер не принимает готовый Score от клиента. Ошибки формата дают HTTP 400, недопустимый сценарий — 422, тело больше 16 КБ — 413. Невалидный сценарий не передаётся модели.

## Ограничения текущей версии

- Синтетические данные, фиксированный каталог и упрощённые эффекты. Пять районов — состав учебного датасета, карта является условной схемой.
- Нет регистрации, базы данных и постоянного сохранения пользовательского сценария; обновление страницы сбрасывает выбор.
- AI ограничен набором подготовленных сервером фактов. Он не рассчитывает Score и не отвечает на произвольные вопросы, для которых нет фактов в сценарии.
- Рекомендации проверяют варианты одной замены, не доказывают глобальный оптимум. Несколько рекомендаций нельзя считать совместно проверенным набором без нового расчёта.
- Внешний AI требует ключа, сетевого доступа и совместимости выбранного endpoint. Доступность модели на опубликованном экземпляре определяется его серверной конфигурацией.
- Кризисы, сравнение команд, отдельная карточка оптимизатора и презентация существуют как экспериментальные прототипы и по умолчанию скрыты. Они не входят в основной демонстрационный сценарий; AI-анализ отключается при активных экспериментальных событиях.
- `VITE_ENABLE_EXPERIMENTS` — настройка фронтенда на этапе сборки. Передача её только запущенному production-контейнеру не включает скрытые элементы; текущий Dockerfile не предусматривает отдельного build-аргумента для этого флага.
- Таймер пятичасовой смены — элемент интерфейса: по истечении времени решения не блокируются.
